## 执行方式

由用户操作真实桌面，我按编号每次引导 1–3 项；收到实际观察后登记结果，有差异先定位再继续。无需一次读完本文。每项必须同时核对操作结果和副作用：只读查询没有派工、排队没有自动运行、模型结束没有冒充验证成功。所有截图如需存档，只截测试数据和应用区域。

结果只能是：待执行、执行中、通过、失败、阻塞、跳过、不适用。用户口述记为“用户观察”；我读取账本/文件记为“Host 只读核对”，两者分别记录。预期拒绝只有观察到拒绝及无副作用才通过。条件未出现不是通过。模型措辞可变化，以实际对象、动作、版本、账本和产物为准。

回归遵循用户最新约定：默认只做受影响范围的增量检查；全量仅用户明确要求时运行。本文的完整用例库是可逐项执行的覆盖清单，不代表每次修复都重跑全量。

默认顺序：A → B → C → D → E → F → G；S 是分开的协助验证。A/B/C、E01–E05、F、G01–G05 不需要新模型推理。D、E06–E08、G06 含真实推理，按钮前会单独说明次数；不为了凑用例反复生成提案。模型已发送后若等待超时/结果未知，只核对原记录，不换标识重发。没有自动化故障注入时，审批/断线/清理重试等分支可能记“条件未出现”，随后按 S 类单独补测。

完整走查可分多次完成，纯人工操作约 60–100 分钟，模型等待及问题定位另计。核心首轮推荐 A01–A06、B01–B04、C01–C04、D01–D03/D06–D07、E01/E03/E06/E07、F01、G01–G03；其余边界与协助项仍保留，不以核心首轮替代完整结果。

启动器只设置独立 Electron `userData`，导入生产 Main，不传 smoke 参数、不替换后端、不主动发送模型任务、不关闭沙箱。Node/Electron/CLI 仍用本机锁版和受支持的现有登录，不复制认证。`--prepare` 仅准备目录，`--preflight` 仅允许无项目/Task/Run/Intent、无Source配置/已激活恢复代的空档案，构建并短暂启动真实窗口验证隔离/安全配置后退出；预检不算人工走查。正常启动会恢复自己之前确认的有效计划，所以后续按F/G要求先处理运行状态。
