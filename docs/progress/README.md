# 阶段进展与同步

每个 M 分为四个进展点。进展点完成或出现具体外部阻塞时，更新阶段记录并同步：已完成、验证证据、阻塞/风险、下一步。进展点是交付检查点，不把静态检查通过等同于功能可用。

**提交与推送规则**：每完成一个进展点，先落盘本点总结与验证证据，再创建 Git 提交并推送远程 `main`，核对远程提交后同步提交号。推送失败按原检查点继续处理并记录原因；不使用强制推送，不把未通过的阶段 Gate 标为完成。后续检查点只记录实际新增结果，保留失败/阻塞与修正轨迹。

可选能力未启用时记录“不适用”及原因，不能标为测试通过。Browser/Computer 与 DeepSeek 使用独立能力 Gate，不阻塞基础桌面阶段。M0/M1 共享同一安全窗口骨架，M0 只验收连接和预览，M1 才验收完整代码工作流。

当前：[M0 进展](M0.md)：M0.1、M0.2 与 M0.4 桌面子项完成，M0.3 受代理 CONNECT 403 阻塞，整个 M0 Gate 尚未通过。总体范围与工作包见[开发规划](../design/00_总体架构与开发规划.md)。

具体用例在各工作包真实开发时与实现并行细化；未来阶段继续只保留验证要求。每次运行记录目标、环境/版本、发现/执行/跳过数量、实际结果与脱敏证据。没有运行的检查明确标为未运行。

## 同步记录格式

- 进展点、状态、涉及工作包。
- 已完成的行为及可检视产物。
- 实际运行的命令/目标和结果；真实组件、Stub 与模拟器分别说明。
- 阻塞项及需要的具体外部条件；不索取或记录密钥值。
- 下一步及对应进展点。
