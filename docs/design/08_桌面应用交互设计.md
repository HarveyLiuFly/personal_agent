# 桌面应用交互设计

更新日期：2026-11-05。适用阶段：M0–M3桌面交互整合，后续M4–M5沿用。对应工作包：UI-201信息架构、UI-202连续对话、UI-203任务审阅、UI-204目标与记忆、UI-205验证与可访问性。本文件是当前交互设计；协议、执行与隐私规则仍由相关专题定义。

## 1. 问题与设计目标

本轮真实走查52项通过只说明相应功能和边界成立，不能说明产品易用。当前产品按Host模块摆放功能：主聊天是模态窗口，规则聊天和模型提案各有输入框；执行记录按Run平铺而非按任务组织；预算/资源/备份占据主内容；目标编辑要求JSON与核验ID，记忆要求用户手抄来源和引用。用户需要理解内部机制才完成日常工作。此次重构解决上述工作流问题，保留真实Store/Gateway/Intent，不以合成聊天代替执行。

目标：打开项目即可输入，发送后能看到进展和结果；切换任务能找回原上下文；变更和验证紧邻结果；复杂操作先用可读表单表达，详细技术信息按需展开。默认页面不显示UUID、JSON、Epoch、Lease、协议版本或Token账本大卡片。

## 3. 信息架构与布局

三块区域：左侧项目和任务导航（约240px）、中间连续工作区、按需展开的变更/文件辅助区域。顶部只有当前上下文标题和常用工具；连接/资源信息移入侧栏底部与设置。任务数量/待处理状态在侧栏可见。文件、终端、工作树继续走真实现有API，位于工作区工具入口，工作树管理和终端默认折叠以留出预览空间。无项目时显示“打开项目”明确空态。

导航（CORE.2d 起）：侧栏顶部是 Dot（个人助手，CORE.5 前仍按当前项目工作），其下是“新对话”、标题搜索和对话清单；辅助页面是任务与计划、目标、记忆、自动化、设置。对话清单来自账本：置顶在前，按最近活动排序，按页加载（“更多对话”）；每行标出需批准/需回答/需核对、运行中、未读，选中后不被后台更新抢走。项目对话不经过路由，用户消息直接成为该对话的下一轮。历史原生Thread浏览为“原生历史”辅助入口，不能拿Context JSON作主要会话名。权限正式管理仍M5，页面不得伪造未实现的授权、MCP、插件或子Agent按钮。

每个中心页面有唯一主要滚动区；输入框固定在工作区底部。长回答不限制在240px的pre中。只有代码/原始证据使用等宽字体，普通对话使用正文排版。宽窗口可并看工作/变更，窄窗口工具面板可关闭，不挤压输入到不可用。按钮有明确aria-label、focus-visible和disabled原因。

## 4. 连续对话与任务

### 4.1 Dot（原项目助手）

用户在唯一输入框描述问题。明确规则命令仍用submitMainChat；自然语言用现有proposeMainChat保存Message/Intent并生成结构化结果。原消息立即显示，处理期间显示阶段而非留空。提案和回答按Message ID与该消息相邻展示。

新发送在路由记录上标记 `autoAnswer`；提案形成后，若严格仅一个无依赖 CHAT、对应 pending Step，且距发送不超过 10 分钟，由 Host 后台推进直接提交，作为“发送问题”授权的只读回答，不依赖页面是否挂着（CORE.2e，修 L11）。没有该标记的历史提案、超过时限的提案、任何未知请求都不自动提交。达到并发上限或项目正忙时提案保持“等待空闲”，有空位后由 Host 开始（修 L10）；其他无法开始的原因直接标为失败，均未发送。Host 后台推进覆盖所有未结束的路由，不限最近一页（修 L5）；界面显示最近 50 条消息并提示更早的未显示。只要最终回答完整，其他条目（如长输入）被截断不影响取回答；回答本身被截断时保留已得部分并标注（修 L13）。混合CHAT/创建/更新/续接/暂停/取消/Goal等一律呈现可读计划并由用户明确确认。CLARIFY直接展示问题，不误发执行。后端继续独立Router/Chat profile和最小Intent账本。

不追加自动新键重试。生成或提交未确认时保留精确原请求，禁用新发送，提供“核对这次发送”；显式核对原ID，后台只读刷新不推理。确认后清草稿，输入法composition期间Enter不发送。普通Enter发送，Shift+Enter换行；Cmd/Ctrl+N新对话、Cmd/Ctrl+K搜索对话。草稿仅在Renderer会话内缓存，不把私人内容写入localStorage或新的外部日志。

### 4.2 对话

新对话与继续对话使用同一个输入框。输入框下方选择模型、推理强度和权限（只读 / 自动 / 完全访问）；新对话预选该项目上次的选择（无则“自动”），已开对话的更改从下一轮生效；选“完全访问”时页面内二次确认（不用浏览器弹窗），未确认不生效。Git 项目的新对话可选“环境：本地 / 新工作树”：选新工作树时先按提交键创建托管工作树（重试复用同一个），切换到该工作树后在里面发出第一条消息；工作树没建好时消息不发出。这一轮运行时输入框改为“追加”（补充给正在进行的一轮），旁边有“停止”；追加在这一轮刚结束时不会发出，文字保留可作为下一轮发送。默认只读；“修改代码”通过可读执行范围表单指定允许文件/固定测试，不能推断任意可写范围（CORE.3 改为权限模式）。打开对话显示全部轮次（最新 10 轮，更早的按需加载），每轮下方是该轮状态、错误与可折叠的执行过程；最新一轮运行时可停止，审批/补问内联显示并允许真实回复。只有本对话在运行或结果待核对时才暂停发送，其他对话运行不影响。最新一轮结束后（完成、失败、停止或已验证完成）都可以继续，输入框不收起；遗忘记忆后旧线程不能续接时，提示并提供“从检查点新开线程”。尚未开始的对话（保存的待办）提供“开始”。打开对话即标记已读；对话可置顶、归档（侧栏“已归档”查看，归档后输入锁定，取消归档恢复）。每个结果已知的轮次下有“从这里新开”：新对话带上到该轮为止的内容，原对话不变。

发送失败时：已知的拒绝（容量已满、项目正忙、需先核对等）给出可修正原因，不保留请求编号；其他未确认结果保留草稿和同一个请求编号，可以“再次发送”而不会重复（同一编号只会发送一次）。Unknown 只读核对；代码模型结束显示“待验证”，只读回答结束显示“已回复”，只有可信完成显示“已验证完成”，不把隐藏思考占位当正文。对于缺Goal计划版本的旧续接准备失败，只有原Run无任何Intent/服务请求、明确RUN_GRANT_EXPIRED且Task Fence/隐私策略一致时，显式核对才可确认未发送并以0用量结算；不修补旧授权、不自动另发。项目对话的用户消息就是原文；旧记录中已识别的Host Context wrapper仍提取request内容展示，原始元数据按需查看；不得修改实际提交内容或把模型文本当可信验证。

变更结果在当前任务中查看。验证触发后等待真实Host结果，展示执行/跳过数量和失败原因。核验ID只在诊断详情供复制，日常目标完成由UI取得真实收据，不要求用户抄ID。

## 5. 目标、记忆与自动化

目标默认展示已保存目标与当前计划，创建/调整表单按需打开。计划用行编辑器表达任务内容、前置关系、只排队/明确执行一次，以及代码任务范围。内部key由UI维护；删除依赖节点要同步清理引用。预览必须显示替换范围和派发方式；显式提交才CAS替换，来源订阅仍显示范围并确认。高级JSON可折叠兼容，不是默认路径。

目标完成按钮读取本目标任务的实际Run及验证收据，向Host提交真实verificationIds；缺少通过收据时说明哪些任务尚需验证。最终仍由Host检查所有计划任务、Artifact哈希与当前授权，不得仅凭UI绿色计数关闭Goal。

记忆提供“添加记忆”：名称、内容、范围、隐私级别。保存明确内容时先用真实submitMainChat保存精确/remember确认来源，再调用rememberMessage。失败时保留同Message ID核对；不得凭空制造来源或直接写SQLite。新值修订仍引用新同键确认消息及旧Claim版本；高级证据查看与旧来源不可复用规则保留。来源遗忘表单默认折叠，选定具体来源时才展开。遗忘是明确危险操作，保留范围、确认与逻辑/物理分项收据，不在本轮重构中执行尚未确认的旧删除。

自动化集中展示定时任务；默认只排队。时间有快捷项与默认有效值，时区明确，补发/并发等高级选项按需展开。本机Main后台、退出停止/休眠不执行的边界可查看；不承诺Claude云任务那样离线执行。备份恢复归设置，恢复前摘要/状态戳/安全副本等合同不变。

## 6. 实施范围与验收

本轮完成现有功能的交互整合，不启用云端调度、通用文件写入、浏览器/Computer执行、外部发布、正式权限管理或竞争产品的所有能力。每个入口必须真实接线；不可用项说明原因，不放可点击空按钮。

UI-201：应用壳/导航/主题/自动目录连接/任务搜索。UI-202：单输入项目助手、内联提案与纯CHAT回答、精确未知核对。UI-203：Task聚合/续接/审批/工具折叠/变更验证与草稿。UI-204：目标可读计划/核验收据选择、直接来源化记忆、自动化与设置。UI-205：增量组件/真实桌面、键盘与布局、真实模型链验证。

### 开发验证要求

具体用例在真实开发时与实现并行细化，记录规划、执行、失败和复走。增量检查：新会话展示/纯CHAT自动提交守卫/Context渲染/IME/草稿隔离的有意义组件测试；受影响主聊天/路由/任务/记忆/Goal合同；TS/构建/设计导航检查。常规不跑全量。真实Electron CUA在Sculptor扩展屏操作公开专用档案；至少验证无模态首屏、切换/搜索、保存待办、草稿恢复、计划行编辑、来源化记忆、Diff/验证、设置备份入口及窄窗口布局。模型用例单独记录真实Run/Intent/用量，元数据/Fixture不能冒称模型成功。若实际认证或上游阻塞，保留原Unknown且不重发，不把未验范围写通过。

验收任务：自然语言问题一次输入后能看到真实回答；创建待办不会生成Run；代码任务只改允许文件并取得Host独立收据；目标计划与完成无需编辑JSON/抄核验ID；添加/修订记忆有真实原消息；旧Task/Thread和未知请求不被重构意外激活；模态关闭/项目切换不导致错误归属或重复提交。可用性判据和实际步骤数分别记录，不能把目标步骤数当已测量结果。
