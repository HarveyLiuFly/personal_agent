# M4–M5：多设备接入与产品化技术方案

适用阶段：M4 设备入口；M5 正式产品化  
实施状态：技术方案与验证要求已定义；具体用例在真实开发时与实现并行细化，应用结果另行记录。  
总体入口：[总体架构与开发规划](00_总体架构与开发规划.md)

## 1. 实施边界与输入

**目标**：把手机/眼镜接入同一 Dot，并完成身份、分发与可选云端的可控扩展。

**前置条件**：M3 已提供可靠 Source、Task/Message ID、投递/ACK、隐私与撤销；真实硬件权限需在对应平台验证。

**对应工作包**：`DEVICE-001`、`RELEASE-001`、`RELEASE-002`。工作包的定义与阶段 Gate 统一见总体规划。

**共用合同**：[领域接口](contracts/domain.ts)、[数据库结构](contracts/schema.sql)、[协议能力矩阵](contracts/protocol-capabilities.json)。本专题定义所属领域的语义，直接引用共用合同，不复制第二套 Schema。

**协作边界**：事件准入和结果状态见[调度自治方案](04_M2_M3_事件调度与长期自治.md)；敏感操作和批准见[可信执行方案](05_M2_M3_可信执行与ComputerUse.md)。

## 2. 多设备与后续身份能力

眼镜负责用户发起的 Camera/Mic/触摸事件与简短反馈；手机负责本地语音/轻量过滤、系统权限、配对、通知和可信批准界面；Desktop/Cloud Dot 持有唯一 Goal/Task/Memory 权威。

ContextEvent 包含稳定事件 ID、配对 Device ID、序号/防重放字段、发生时间、隐私类别、用户发起标记、受控媒体引用和回复通道。设备时间仅作来源信息，接收与计划使用 Runtime 时间。重传复用 ID，持久化成功后才 ACK；设备不能凭断线前状态宣称任务完成。

原始视频/持续环境流默认不上传；优先本地过滤与最小事件。`local_only` 数据不送云端模型。设备审批绑定具体 Proposal/账号/Hash/Epoch；语音“同意”不能在缺少确定提案和可信交互时变成交易凭证。

M5 的 AuthProvider 管理正式登录、取消授权、账号切换与可选云租户。Profile 数据与 OS Keychain/受保护连接有明确归属，切换后不共享 Browser、Thread、Memory、Grant 或缓存。云端服务需独立认证、每租户权限/存储/密钥/网络策略与灾备，不能只加 `owner_id` 字段就宣称隔离完成。

## 3. 设备协议与同步合同

| 信息 | 必须保持的语义 |
|---|---|
| Event ID / Device ID / Sequence | 来自已配对身份，同一事件重传复用 ID；异常乱序/重放有确定处置 |
| occurredAt / receivedAt | 设备时间是来源信息；服务端接收/计划时间独立，不因设备改时而重复执行 |
| 用户发起标记 / 隐私类别 | 决定可接入范围；local_only 不能被网络重试变成云端上传 |
| 媒体引用 | 受控、限量、期限明确；不把原始持续视频混入每条事件 |
| Reply Channel / ACK | 存储后 ACK，结果可重取；ACK 不等于业务完成 |
| 审批与撤销 | 绑定受保护 Proposal/Hash/Epoch，过期或已消费请求不能因设备重连再次获准 |

M4 先用配对模拟器实现同一 Source 语义，再验证真实手机权限、弱网、通知、音频打断与眼镜输入/回显。模拟器通过和真实硬件通过分别报告。跨设备更改目标使用同一版本条件更新，不让设备本地缓存成为权威。

## 4. M5 权限管理、身份、发布与云端边界

权限管理统一在 M5 实施：角色/能力配置、授权与审批管理、执行域/控制状态隔离、权限审计及跨平台 named-profile 基线。M2 先交付本机功能，沿用既有 Intent、版本/Fence、预算、IPC 来源校验和原生/Electron 沙箱；不因延期移除这些底线，也不把未实现的隔离声称已通过。已开展的受控权限原型和限制留在进展/本机归档，不作为 M2 的持续开发前置。具体用例在 M5 实现时并行细化。

正式 AuthProvider 管理账户生命周期与受支持的第三方授权，凭据由 Keychain/受保护服务持有。Profile 切换要排空或明确隔离旧执行，不保留跨身份的 Browser、Memory、缓存或批准；用户退出后仍在排队的工作不能继续使用已撤销连接。

发布链固定依赖、签名与更新来源，提供安装、升级、失败恢复与数据兼容证据。未知协议/Schema 不静默迁移。SBOM、许可证、品牌和第三方服务使用约束在公开分发 Gate 中核对。

云托管、多租户、计费是可选产品能力，不是 M4 必须条件。启用时独立验证每租户数据/密钥/网络/会话边界、配额、备份恢复和运营权限。没有部署对应能力时标为未启用，不能用本地单 Profile 测试宣称云端隔离通过。

## 5. 交付顺序

设备配对/模拟事件 → ACK/重传/结果同步 → 隐私与审批同步 → 真实手机/眼镜 → 正式 Auth 与账户切换 → 签名发布/更新 → 可选云端与计费。每个交付只开放已验证路径，并保留清晰的禁用和撤销入口。

## 6. 开发验证要求

以下只规划 M4/M5 必须覆盖的验证范围与验收证据。具体输入、步骤、Fixture、故障注入方式和自动化实现，在对应工作包真实开发时并行细化。当前不宣称已经形成完整用例库或通过应用验收。

| 验证方向 | 必须覆盖 | 验收证据要求 |
|---|---|---|
| M4 配对与事件 | 非法设备、重复/乱序/重放、设备时间偏差 | 可信 Source、稳定 ID 与明确丢弃/接受处置 |
| M4 ACK/弱网 | 断线、重传、存储前后失败、结果重取 | 持久化后 ACK，未完成/Unknown 不虚报成功 |
| M4 隐私/审批 | local_only、媒体最小化、批准绑定、过期与撤销 | 实际数据流和有效提案/回执，无自动扩权 |
| M4 真实设备 | 手机系统权限/通知/音频、眼镜输入与回显 | 模拟器与具体硬件/平台结果分别记录 |
| M5 权限管理 | 角色/能力、授权/撤销、控制状态与执行域隔离、平台差异 | 原生拒绝与正常能力分别验证；不以配置或元数据替代隔离证据 |
| M5 身份/发布 | Profile 切换、登出/撤销、签名/更新、备份/兼容性恢复 | 实际数据/进程归属、安装升级和回滚证据 |
| M5 可选云能力 | 租户隔离、配额/计费、运营权限和灾备 | 仅启用能力才列入对应 Gate；本地结果不冒充云验收 |

每项实际验证记录正常/失败/拒绝/恢复结果，区分真实组件、Stub、模拟器和外部阻塞；执行状态与证据格式遵循[总体规划](00_总体架构与开发规划.md)的开发验证规则。
